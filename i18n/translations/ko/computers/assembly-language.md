# 어셈블리 언어와 머신 모델

> **Domain:** computers | **Difficulty:** journeyman | **Safety:** green

*참고 자료로만 사용십시오. 이 정보를 원자료와 자격을 갖춘 전문가와 대조해
확인한 뒤 행동에 옮기십시오. 이 항목은 단독 정보 원천이 아닙니다.*

## 개요

어셈블리는 프로세서가 실제로 실행하는 것을 텍스트로 옮긴 것이다. 기계가
레지스터와 메모리 사이에서 데이터를 어떻게 옮기고, 어떻게 분기하며, 스택을
어떻게 쓰는지 보여 주므로, 시간이나 메모리를 낭비할 수 없는 시스템의 일부를
다루기에 가장 알맞은 도구다. 핵심 원칙은 아키텍처가 하나의 계약이라는
점이다. 명령어 인코딩, 레지스터 집합, 그리고 호출 규약이 모두 고정되어 있으므로
이 규칙을 지키는 코드는 컴파일러, 라이브러리, 앞으로의 개정판을 가로질러
올바르게 동작한다.

## 선행 조건

- 임베디드 C 프로그래밍
- 이진수와 십육진수 계수법
- 불 논리와 2의 보수
- 메모리 맵과 프로세서 데이터시트 읽기

## 재료 및 도구

- 디버그 프로브가 달린 Cortex-M 보드, 또는 디스어셈블러가 있는 호스트 머신
- objdump과 nm 유틸리티를 포함한 ARM GCC 툴체인
- 명령어 집합과 메모리 맵에 대한 레퍼런스 매뉴얼
- 16진수 보기 기능을 갖춘 텍스트 편집기
- 핀과 버스 타이밍을 관찰하는 로직 분석기
- 알려진 입력을 넣어 주는 테스트 스크립트나 터미널 프로그램

## 작업 절차

### 명령어 집합 익히기

1. 아키텍처의 레지스터 집합을 나열한다. R0에서 R12까지 13개의 범용 레지스터, 그리고 스택 포인터, 링크 레지스터, 프로그램 카운터, 그리고 음수·영·올림·오버플로 플래그를 담는 레지스터가 있다.
2. 주소 지정 방식을 적는다. 레지스터 지정부터 즉시값 지정, 레지스터 오프셋과 레지스터 간접 지정, 스택 push와 pop까지 각각 한 줄짜리 예를 든다.
3. 인코딩을 적어 둔다. 기본 인코딩에는 16비트 명령어가, 확장 인코딩에는 32비트 명령어가 있으며, 32비트 명령어는 4바이트 경계에 놓여야 한다.

### 디스어셈블리 읽기

1. 디버그 정보를 넣어 작은 C 함수를 컴파일하고 objdump 유틸리티로 디스어셈블한 뒤, 각 C 줄을 대응하는 명령어와 맞춘다.
2. 레지스터를 저장하는 프롤로그, 본문, 그리고 레지스터를 복구하고 링크 레지스터로 되돌아가는 에필로그를 찾아낸다.
3. 목록에서 스택 프레임 크기를 찾아, 같은 함수에 대해 컴파일러가 보고하는 값과 일치하는지 확인한다.

### 루틴 작성

1. 처음 두 레지스터로 인수를 받고 첫 레지스터로 결과를 반환하는 함수를 어셈블리로 작성하되, 프로시저 콜 표준을 따른다.
2. 모든 호출 경계에서 스택 포인터를 8바이트 정렬로 유지하고, 반환하기 전에 정렬을 확인한다.
3. 여러 입력값에 대해 루틴을 C 구현과 비교해 결과를 하나씩 대조한다.

### C와 섞고 성능 측정

1. naked 표시는 꼭 필요한 곳에서만 하고, 그 밖의 모든 곳에서는 컴파일러가 호출 주변의 레지스터를 관리하게 한다.
2. 코어의 사이클 카운터로 사이클 수를 측정하고, 각 최적화 수준에서 같은 작업을 C로 작성한 결과와 비교한다.
3. 링커의 맵 파일을 읽어 어셈블리가 플래시와 RAM을 얼마나 아꼈는지 확인하고, 아낀 양이 유지 보수 비용에 비해 의미 있을 때만 남긴다.

## 안전 주의사항

- 어셈블리 루틴은 실행되는 순간 출력 핀을 어떤 상태로든 만들 수 있고, 인터럽트 핸들러 안의 무한 루프는 워치독을 울리거나 머신을 정지시킨다. 구동 장치를 분리한 상태에서 새 코드를 검증한다.
- 어셈블리에서 잘못된 주소에 쓰면 경고 없이 메모리와 주변 레지스터가 손상된다. 쓰기 전에 모든 주소를 메모리 맵과 대조하고, 그 영역이 실행 가능하며 보호되지 않았는지 확인한다.
- 코어의 정렬 규칙을 지킨다. 정렬되지 않은 32비트 접근은 어떤 장치에서는 오류를 일으키고, 다른 장치에서는 조용히 사이클을 낭비한다.
- 한 단계씩 실행하면 프로그램의 타이밍이 바뀌므로, 제어 루프를 단계별로 디버깛하지 않는다. 대신 추적 버퍼나 로직 분석기를 쓴다.
- 하드웨어 리셋, 부트로더, 또는 복구 이미지를 항상 준비해 두고, 의존하기 전에 복구 경로를 시험한다.
- 어셈블리는 기본적으로 유지 보수가 불가능한 것으로 본다. 작게 유지하고, 레지스터 사용을 주석으로 남기며, C 참조 테스트로 덮는다.
